# Noise repository instructions

Keep `README.md` updated as part of every change that affects users or developers.
This includes features and controls, defaults and engines, platform support,
requirements, installation and audio routing, permissions, limitations,
troubleshooting, build instructions, verification status, and release downloads.

- Update the README in the same change as the implementation or release.
- Keep platform-specific guides and the README consistent. Summarize essential
  differences in the README and link to detailed guides.
- Refresh relevant screenshots when the interface changes. Label previews or
  sample data accurately.
- Link to packages that actually exist and show their platform-specific versions
  and signing status. Distinguish shipped features from plans and unsupported
  behavior. Describe validation only when supported by completed checks.
- Preserve historical release notes; document current behavior in the README
  and current guides.
